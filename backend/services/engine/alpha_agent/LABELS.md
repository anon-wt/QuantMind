# 统一预测标签与周期

三种挖掘入口共用 `prediction_horizon`（1～250 个交易日，默认 1）。
原始 Y 固定为 `close[t+h] / close[t] - 1`，从信号当日收盘计。
`label_contract.py` 是公式、参数归一化、历史周期推断和收益序列的唯一入口。
缺失某日价格时该标签为空，不跳到下一条股票记录，也不跨股票移动。

入口链路：前端统一周期 → preview/evolve → 任务参数快照 → 算法执行 →
因子 metadata.label_spec → 单个/批量因子作业 request.label_spec → 结果。
周期进入任务指纹及作业快照，后续回测/验证自动继承，不从当前页面默认值重选。
统计新任务只评估该一个周期；GP 内部 horizon 被统一字段覆盖。
RD-Agent 在其现有适配器内重写安装包的 LABEL0 模板，保留原有标签标准化；
缓存键加入标签，防止不同预测目标复用旧实验成绩。

挖掘、OOS 和独立回测都不读取窗口结束之后的价格作为标签。
RD-Agent 的 train/valid/test 分段尾部各预留 h 个交易日，使标签终点留在本段。
预测周期超过数据或分段可用长度时应失败或报告有效日不足，不用其他周期补齐。

逐日 IC 可以使用重叠 h 日标签。组合净值每 h 个有效交易日选一次组合，
使用不重叠持有期收益；年化缩放为 252/h，成本按实际选中的调仓日期计算。
曲线日期为信号日，series.date_basis 显式记录 signal_date。
这是单因子分组组合分析，模型策略的独立交易规则继续由其策略配置管理。

旧结果和已提交作业不重写。历史因子新提交作业时优先读取显式 label_spec；
没有时读取统计 evidence.best_horizon、GP gp_config.horizon，最后回退 1 日。
历史 RD-Agent 使用过延后一天的 LABEL0，其已有成绩保留，新提交回测按统一起点计算。

函数式因子的用户代码仍由现有 Docker 控制器执行，只输出数值；标签和指标在
受信任的 factor_job_executor 中计算，与统计/GP 共用同一实现。
`factor_values_sandbox.py` 是此数值模式的固定容器入口；源码通过原有沙箱清单
提供，保持只读文件系统、无网络、无凭据和资源限额。准备的公共面板最多 100 万行，
沿用完整面板的字段富化机制和 250 根预热；不依赖全量历史 HDF 缓存。

所有新增信息存储在既有 JSON 快照及 metadata 中，不增加数据库表。
